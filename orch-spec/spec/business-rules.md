# 业务规则和约束（主规范库）

> 本文件汇总各需求归档的业务规则/约束。新增规则以 `##` 追加。
> **规则1 北极星原则为主规范最高优先级规则**，适用于全部归档需求。
>
> 首个归档来源：plugin-capability-optimization（插件本体全方位能力优化）。

## 规则1: 北极星原则（最高优先级）

**描述**：插件的存在是在最大化发挥模型自身能力的前提下提供项目实现的约束；约束绝不能造成模型能力被限制。约束 = 护栏（防坠落），不是牢笼（限奔跑）。

**规则表述**：
```
IF 任一约束/流程/格式要求会削弱模型思考深度、探索自由或创造性
THEN 该约束为反模式，需降级为建议或移除
```

**示例**：
```
IF 阶段纪律仅约束"流程顺序与产出存在"
THEN 保留（护栏）
IF 阶段纪律限制"思考深度/探索方式"
THEN 降级为建议（牢笼）
```

**优先级**：最高
**相关场景**：S1 Case3（GATE 审查）

## 规则2: 自动化边界 = 规则自决 + 白名单人工

**描述**：智能 gate 的裁决机制。可裁决分支自动补偿，白名单场景暂停等人工。

**规则表述**：
```
IF 错误属于"编译/测试失败/缺文件/步骤重试"
THEN 自动补偿继续（重试 1-2 次/自动补建/降级重试）

IF 场景属于"需求冲突/验收不确定/HARD-GATE卡点/跨仓库变更"
THEN 暂停等人工（白名单触发）
```

**优先级**：高
**相关场景**：S6 Case2（流转率）

---

## 规则3: 量化验收阈值

**描述**：本次优化必须达成的量化指标。

**规则表述**：
```
IF 自动流转率 >= 80%
AND 产出达标率 >= 90%
AND 容错自动恢复率 >= 80%
AND 每块有验证闭环
THEN 优化验收通过
```

**优先级**：高
**相关场景**：S6 全部

---

## 规则4: 不关注 token 消耗

**描述**：本次优化将 token/成本消耗从约束中移除，专注能力优化。

**规则表述**：
```
IF 优化方案为提升能力而增加 token 消耗
THEN 允许（不视为违规）
```

**优先级**：高
**相关场景**：全部

---

## 规则5: 引用完整性

**描述**：所有 SKILL.md/agent/command 的引用必须指向存在的文件。

**规则表述**：
```
IF 文档引用路径指向不存在的文件
THEN 修复引用或补充文件（禁止悬空引用）
```

**示例**：
```
project-map.md → project-map.json
context-injection-protocol.md → context-inheritance-protocol.md
```

**优先级**：高
**相关场景**：S2 Case1、S3 Case1-2

---

## 约束1: 修改范围

**描述**：只修改探索审计定位的薄弱环节，不做无关重构。

**约束表述**：
- 修复 P0×2/P1×2/P2×2/F1-F12
- 不"改进"相邻代码/注释/格式（除非是审计定位项）
- 遵循现有 style

---

## 约束2: 插件机制限制

**描述**：plugin.json 只声明 skills+commands；禁止声明 agents/hooks。

**约束表述**：
- 禁止在 plugin.json manifest 中声明 agents/hooks
- agents 按 agents/*.md 自动注册
- hooks 按 hooks/hooks.json 加载

---

## 约束3: 验证证据

**描述**：每条验收标准必须有新鲜证据。

**约束表述**：
- 拒绝"应该/可能"式声明
- 覆盖率高必须有命令输出
- 修复必须有 grep/运行验证

---

## 约束4: 测试先行的边界

**描述**：TDD 强制，但测试必须服务于能力验证，不限制模型实现自由。

**约束表述**：
- test-*.template 存在才允许编码（标准模式）
- 覆盖率 ≥85%（标准模式）
- 测试定义 WHAT（行为），不限制 HOW（实现）

---
