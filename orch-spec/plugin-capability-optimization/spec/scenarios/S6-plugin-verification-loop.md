# 场景: S6 插件验证闭环建立

**优先级**：高
**相关场景**：S1-S5 全部
**场景间依赖**：
- depends-on: S1、S2、S3、S4、S5（全部优化完成）
- provides-to: 无（最终验收）

---

## 场景描述

建立插件自身的完整验证闭环，确保"每块有验证闭环"的验收标准达成。通过统一的自检入口，验证 5 大块优化后的状态，并实现量化验收指标的可测量性。

---

## 前置条件

- S1-S5 优化全部完成
- 自检命令已建立（S4 Case1）

---

## Case 1: 全量自检跑通

**目标**：5 大块优化后，统一自检命令全量 PASS

**WHEN**
```
- 运行插件自检命令（/orch:self-check 或等效脚本）
- 检查 ①编排 ②Agent ③Skills ④TDD闭环 ⑤Commands+Hooks
- 每块有对应验证项
```

**THEN**
```
- 5 大块全部 PASS
- 输出每块验证项与结果
- 任一 FAIL → 定位到具体文件与修复建议
```

**数据**：
```json
{
  "blocks": {
    "orchestration": "PASS",
    "agents": "PASS",
    "skills": "PASS",
    "tdd_loop": "PASS",
    "commands_hooks": "PASS"
  }
}
```

---

## Case 2: 自动流转率测量

**目标**：验收"自动流转率 ≥80%"——新工作流从 spec 到 execute 不依赖人工干预的流程段占比

**WHEN**
```
- 启动一次测试性工作流（模拟需求）
- 统计 spec→test-design→design→task→execute 各段
- 记录每段是否需人工干预
```

**THEN**
```
- 计算自动流转率 = 无干预段 / 总段
- ≥80% → 达标
- <80% → 定位瓶颈段，输出优化建议
- 结果写入测试报告
```

---

## Case 3: 产出达标率测量

**目标**：验收"产出达标率 ≥90%"——二次审查达标通过率

**WHEN**
```
- 对优化后的插件产出（规范/设计/代码/测试）执行二次审查
- 统计审查达标项
```

**THEN**
```
- 计算达标率 = 达标项 / 总审查项
- ≥90% → 达标
- <90% → 定位低分项，输出改进方向
```

---

## Case 4: 异常情况 — 量化指标测量失败

**目标**：量化指标无法测量时的处置

**WHEN**
```
- 自动流转率/达标率/恢复率无法直接测量
- 缺少测试性工作流或审查数据
```

**THEN**
```
- 降级为"证据化验收"：列出已修复问题清单 + 自检 PASS 报告
- 标注指标为"estimate"而非"exact"
- 提供后续测量建议
```

---
