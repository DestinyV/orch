## 目标

对 **orch 插件本体**进行全方位能力优化（**不关注 token 消耗**），系统化改进 5 大块：

1. **工作流编排引擎** — workflow 状态机 / 中断恢复 / HARD-GATE 卡点 / 调度逻辑
2. **Agent 体系（25 个）** — 提示词质量 / 派遣策略 / 审查能力 / 协作模式
3. **Skills 指令（22 个）** — SKILL.md 完整性 / 可执行性 / 触发准确性
4. **TDD 执行与测试闭环** — execute / test 阶段闭环 / 覆盖率验证 / 异常处理
5. **Commands + Hooks** — 14 命令 / hooks 注册表 / 自动化事件

## 约束

- **不关注 token 消耗**（cost / 上下文预算不作为优化约束）
- **自动化边界 = 规则自决 + 白名单人工**：
  - **自动继续（规则可裁决）**：编译/测试失败自动重试 1-2 次、缺文件/缺依赖自动补建、步骤重试自动降级
  - **暂停等人工（白名单触发）**：需求冲突/规范矛盾、验收标准不确定、HARD-GATE 阶段卡点、跨仓库/外部依赖变更
- 保持插件核心工作流（SDD+TDD 13 步）语义不变，只增强能力
- 多平台能力对齐（Claude Code / Cursor / Gemini CLI / OpenCode / Codex / CodeBuddy）
- **北极星原则（最高优先级）**：插件存在的意义是在**最大化发挥模型自身能力**的前提下提供项目实现的约束；约束绝不能造成模型能力被限制。约束=护栏（防坠落），不是牢笼（限奔跑）。所有优化必须用此原则审查：任何流程/阶段纪律/格式要求，若削弱模型思考深度、探索自由或创造性，即为反模式。

## 验收标准

- [ ] **自动流转率 ≥80%**：新工作流从 spec 到 execute 不依赖人工干预的流程段占比 ≥80%
- [ ] **产出达标率 ≥90%**：规范/设计/代码/测试二次审查达标通过率 ≥90%（返工率 <10%）
- [ ] **容错自动恢复率 ≥80%**：中断/失败后无需人工介入的自动恢复率 ≥80%，其余 20% 给出明确纠正指引而非静默卡死
- [ ] **每块有验证闭环**：5 大块均有可运行的验证用例或自检命令，优化后全部跑通
- [ ] **智能判定生效**：核心决策/冲突/异常由 gate 智能判定是否人工介入（规则自决 + 白名单机制实际落地）
